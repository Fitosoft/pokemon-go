# Public migration history

The historical files preserve the original migration identifiers and ordering. The structural SQL is retained except for the instance-bound project reference constraint, which is generalized. Private metadata seeds, pilot records, and instance-specific release decisions are omitted or replaced by generic contract stubs. These files are **not byte-identical** to the applied production history and must not be used to repair or replay that history. A fresh installation stays in `building` until its owner validates and authorizes it. Project context tables are installed without private role/configuration seeds. Initialize locally as described in docs/project-context.md. The original SQL remains in the deployed Supabase migration ledger. `../schema.sql` is a psql reconstruction entry point, not a standalone pg_dump. Requires PostgreSQL 17 and the standard Supabase roles; use a disposable database, never the existing deployment. The role migration requires CREATEROLE and must run as the schema owner (postgres). No password is supplied.
